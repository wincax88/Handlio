# Handlio 架构与产品设计

Handlio 采用模块化单体：React / TypeScript / Vite 前端，Express / TypeScript API，SQLite 关系数据和私有文件目录。默认面向单应用实例，便于本地运行和受控试用。水平扩容前需迁移数据库、私有对象存储和跨实例任务租约，不应直接共享一个 SQLite 文件到多台机器。

## 用户和信息架构

创作者为独立开发者、实施顾问和小型工作室负责人。每个创作者拥有一个工作区；客户只加入某个项目。英文是首版界面语言，正文支持中文。创作者工作台包括项目总览、截图、三栏指南编辑器、手册与检查、版本、交接中心、导出、账单和设置。客户阅读端保留目录、搜索、步骤链接、图片缩放、历史版本、问题和明确收件确认。

视觉方向为暖白纸面、深色文字和森林绿状态色。主操作优先突出“下一步”，而不是装饰性图表。无数据时使用真实空状态；不把阅读、确认和发布混为一个完成率。

## 数据与职责

| 模块                | 主要实现                       | 核心保证                                                                |
| ------------------- | ------------------------------ | ----------------------------------------------------------------------- |
| Identity            | `auth.ts`                      | 邮箱、用途、邀请范围绑定的哈希验证码；限流；安全 Cookie；CSRF；重新验证 |
| Workspace / Project | `routes.ts`, `domain.ts`       | 工作区从会话获取；项目归属校验；免费额度；生命周期                      |
| Content             | `shared/model.ts`, `routes.ts` | Zod 字段和长度校验；稳定 ID；乐观修订号；无正文离线缓存                 |
| Assets              | `image.ts`, `image-worker.mjs` | 浏览器画布合并；服务端魔数、尺寸和重编码；子进程隔离；私有逐请求读取    |
| Release             | `domain.ts`, `jobs.ts`         | 检查绑定修订号；递增版本；原子快照；数据库触发器禁止改写                |
| Handoff             | `routes.ts`                    | 成员角色、最早可见版本、问题与确认绑定 release；人数快照；无代签        |
| Billing             | `billing.ts`                   | 服务端金额；订单、交易、事件幂等；核验付款时间；订单权益贡献账本        |
| Jobs / Usage        | `jobs.ts`                      | 持久任务、租约、重试、取消；额度预留与结算；完成时复核权限              |
| Export              | `export.ts`                    | 同一发布快照；转义 HTML；无远程请求；PDF 目录页码；完整 ZIP             |
| Operations          | `ops.ts`, `providers.ts`       | 邮件 outbox、去重和重试；默认诊断不含客户正文；支持操作审计             |

完整 DDL 在 `server/db.ts`。发布正文存为结构化 JSON，SQLite 负责外键、唯一性、事务和不可变约束。业务金额使用整数最小币种单位，时间以 UTC 毫秒存储。头像和演示名称不引入第三方追踪。

设备风控使用签名的随机 Cookie 与 SQLite 聚合计数，和邮箱 / IP 限流叠加。Cookie 不用作身份授权，数据库不保存原始设备 token、指纹或设备对应邮箱。维护任务清理过期风险记录。

手册语言、时区、固定章节标题与排列存在草稿 JSON 中，通过相同的乐观并发控制保存；发布快照冻结这些设置。`shared/handbook.ts` 为编辑器、阅读目录、正文与导出提供统一的章节映射和旧数据默认值。固定章节不能删除，指南新增 / 删除会同步整理布局引用；复制项目重新映射指南引用，发布剔除隐藏指南，旧快照与确认散列保持不变。

## 安全素材路径

浏览器选择文件后，仅在内存中检查和展示。裁剪、实心遮盖和标注合并到 PNG 位图，用户逐图确认后才发送。完成后释放原位图，留下处理后的预览。服务端先保留存储额度，再在子进程验证真实格式、最大 8,000 单边和 2,000 万总像素，重编码去除元数据。子进程不获得邮件、支付或 AI 凭据；最多 4 个上传槽，解码时限 15 秒。

私有文件名使用服务端 UUID。图片 API 验证项目或发布范围，客户只能取当前可见版本实际引用的资产。安全撤回隔离相关资产、历史版本及导出；新下载立即失败。已下载的离线副本无法收回。

## 保存和发布

停止编辑约 1.5 秒后提交 `baseRevision`。服务端条件更新失败时返回冲突，浏览器保留当前内存内容，提供服务端对照和手工合并。发布前检查只接受已保存修订；检查创建后再编辑就使它失效。警告需理由，安全及支付阻断不可忽略。

Worker 在事务中创建 release、更新 `current_release_id`、终止被新版替代的未完成确认请求，并记录发布任务完成及通知 outbox。失败不会切换当前发布。旧版恢复创建新草稿，不改旧版，也不继承确认。

清单和发布正文共同参与 `sorted-json-v1` 规范序列化散列：对象键按字典排序、数组顺序不变、字符串按 JSON 编码。散列包含安全资产内容哈希。确认请求和确认记录保存 release ID、完整 manifest hash、人员快照及 `receipt-v1` 文案版本。

## 权限与期限

Owner 查看自有项目；Viewer 只读；Reviewer 可在版本上提问并追加自己的线程；Confirmer 增加被指定版本的确认权限。新成员从邀请时的当前版本开始可见。转发邀请不授予转发者的邮箱权限。成员移除或降级会撤销需要重新选择确认人的请求，而不是算作通过。

托管截止按服务端 UTC 判断，客户没有 Owner 宽限期。提前续期不重置当前导出窗口、不增加 AI 次数；原订单额度和期限承诺保存为快照。退款按独立订单贡献处理，旧付款事件不能复活已退款订单。

正文删除先建墓碑、停分享、取消任务，再清理文件与关系数据。财务记录独立保留。任务完成必须检查墓碑、期限、版本和授权，无法通过迟到回调恢复已删项目。

## 运维边界

当前 Worker 是单实例内的持久队列轮询。邮件发送和支付事件有持久 outbox / 收件记录。未决订单每日对账使用独立轮询和按订单持久化的运行租约，支付死信支持带冷却、原因和审计的运营修复；AI 已有成本预算与熔断。跨实例调度、真实供应商对账、异地备份和生产恢复、成本核对及完整性能 / 安全 / 实机审计仍需完成。不会用本地测试结果代替生产验收。具体门槛见 `deployment.md` 和 `implementation-status.md`。
